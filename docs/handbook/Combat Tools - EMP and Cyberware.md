# EMP and Cyberware

## Resolve disablement

1. Start the intended encounter with the required participants.
2. Resolve the supported EMP/Microwaver exposure or successful disablement QuickHack.
3. If an EMP/Microwaver resistance is required, roll Cybertech against DV15; a tie fails.
4. Use the saved chooser or random result to select the required items.
5. Apply the disablement and review affected-item badges and mechanical consequences.

Requests snapshot their method, eligible pool and policies. Reopening does not reroll a saved shortlist, and changing campaign settings does not redraw an existing request.

| Source | Normal number of selections | Lifetime |
| --- | --- | --- |
| Ordinary EMP | 2 | Originating combat ends. |
| Microwaver | 2 | One minute; encounter cleanup also applies. |
| Short Circuit | 3 | One minute; encounter cleanup also applies. |
| Cyberware Malfunction | 1 | One minute; allowed host cascade can affect components. |

## Configure the pool

GM settings control manual/random selection, player selection from all eligible items or a saved limited shortlist, Fashionware/BioWare/foundational inclusion, foundational weighting, host overlap and hardened-item handling. BioWare extensions are explicitly homebrew. Foundation identity uses native item data rather than assuming every limb name is foundational.

Hardened items can be excluded or allowed to consume a pick without becoming disabled. Native installation, source policy, immunity and host relationships also affect eligibility. Carried electronics are source-dependent.

Optional disabled Internal Frame consequences include immobilization, an action penalty and MOVE reduction. Cyberleg penalties account for applicable active native leg-injury modifiers rather than blindly duplicating them.

## What disabled means

Supported native effects and roll contributions are suppressed while the item is disabled; inventory and installation are retained. Supported weapons, DVs and speedware paths exclude disabled items. Overlapping causes are independent: ending one cause does not restore an item still disabled by another. Preexisting native disabled states are preserved.

Combat end/reset/deletion clears the applicable combat-bound causes. Timed causes can also expire normally. An ordinary generic **Disabled** item marker is only a visual annotation; it does not invoke these mechanics.

General out-of-combat EMP disablement is not provided by this workflow. Do not simulate it by editing the saved request flags.
